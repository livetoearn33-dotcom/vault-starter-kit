# 知識庫搭建包 v0.3

一包給朋友的保母級 SOP。你不用懂程式，把 `START.md` 貼進 Claude Code，它會像教練一樣一步一步帶你把自己的 Obsidian 知識庫搭起來。

搭出來的東西長這樣：一套資料夾規則、一份寫給 AI 看的 `CLAUDE.md`、一個「等我決定」的隊列、一個 AI 問答歸檔區、一份每週健康檢查。之後你跟 AI 講「幫我存起來」，它知道要放哪、要補什麼欄位、哪些地方它不准碰。

## 一行啟動

三種拿法，挑一種：

**1. 直接叫 AI 讀（最快，不用下載）**

打開 Claude Code，貼這一行：

```
請讀 https://raw.githubusercontent.com/livetoearn33-dotcom/vault-starter-kit/main/START.md 並照做，我要搭自己的 Obsidian 知識庫。
```

**2. `git clone`（推薦，之後有更新可以 `git pull`）**

```
git clone https://github.com/livetoearn33-dotcom/vault-starter-kit.git
```

**3. 下載 zip（完全不想碰指令）**

到 `https://github.com/livetoearn33-dotcom/vault-starter-kit` 按綠色的 Code 按鈕 → Download ZIP，解壓縮就好。

拿到之後：先讀 `架構導覽.md`（八分鐘，知道這套在幹嘛），再把 `START.md` 全文貼進 Claude Code。不想先讀導覽也可以，`START.md` 的第 0.5 步會用十行講完重點。

## 這包解決什麼問題

多數人的筆記軟體最後都變成垃圾場：東西丟進去，再也找不出來，AI 也讀不懂。

這包給的是一套「AI 先存、人後裁決」的分工：

- **AI 負責搬運**：剪貼、歸檔、補標籤、每週整理索引
- **你負責認證**：每篇筆記結尾三行（為什麼留／下一步／相關），這三行就是你的簽名
- **等你決定的事有專門的家**：AI 想做又不敢做的事，全部排進一個隊列檔，你一週處理一次

沒有你的判斷，知識庫就只是網路資料的副本，AI 從裡面讀不到別人沒有的東西。有了那三行，它才開始像你的第二個腦袋。

完整的設計理由、結構圖、以及每個預設值可以改成什麼，都在 `架構導覽.md`。

## 適合誰

- 有在持續產出的人：寫文章、做內容、跑專案、接客戶、寫報告
- 已經在用 AI 工具，覺得每次都要重講一遍背景很煩
- 收集了一堆連結和截圖，但從來沒回頭用過
- 願意每週花 20 分鐘做一次維護

## 不適合誰（勸退名單，看到自己就別做了）

- **沒有輸出目的**：只想「把知識整理好」，但整理完不打算拿它做任何事。這套系統的價值全在出口，沒有出口就是白工。
- **想要一次到位的完美結構**：這套是會長歪、要每個月修的活系統。追求一次設計完就不用改的人會很痛苦。
- **不打算用 AI 讀你的筆記**：那你只需要一個資料夾加搜尋，不需要這一包。
- **手上素材少於 20 篇**：先累積，累積到你自己開始找不到東西了再回來。
- **完全不想碰命令列**：Claude Code 是終端機工具，雖然全程只要打字聊天，但你得能開啟終端機視窗。

## 怎麼用（三步）

**第一步：裝兩個東西**

1. Obsidian（obsidian.md，免費）：裝好之後開一個新的 vault，或直接用你既有的。
2. Claude Code（claude.com/product/claude-code）：照官網指示裝，它是在終端機裡跑的 AI 助理。

**第二步：在 vault 資料夾裡開 Claude Code**

打開終端機，切到你的 vault 資料夾（就是 Obsidian 那個資料夾），輸入 `claude` 開始。

**第三步：把 `START.md` 全文貼進去**

貼完按 Enter，Claude 會自己接手：先用十行講完這套架構在幹嘛，問你要照預設走還是先看哪些地方可以客製，然後五個問題，然後一步步蓋。你只要回答問題、看它做的東西順不順眼、說「可以」或「改一下」。

## 大概要花多久

| 階段 | 時間 |
|---|---|
| 裝 Obsidian 與 Claude Code | 20 到 40 分鐘（第一次裝比較久） |
| 讀 `架構導覽.md`（或聽 AI 講第 0.5 步） | 8 分鐘 |
| 跑完 `START.md` 九個步驟（第 0 步到第 7 步） | 30 到 50 分鐘 |
| 搬既有的筆記進來 | 看你有多少，可以慢慢搬，不用一次做完 |
| 之後的維護 | 每週 20 分鐘 |

第一天結束你會有一個能用的骨架加第一篇筆記。真正上手大概要兩到三週，因為你得養成「順手丟給 AI 存」的習慣。

## 跟那篇 Obsidian 爆文（Karpathy、Kepano）的關係

最近有一篇萬字長文在講兩件事：Karpathy 提的 LLM-Wiki（原始資料、編譯後的維基、AI 問答輸出三層，加每週健康檢查），還有 Kepano 的警告（主庫要維持乾淨，AI 產出另開一個亂庫，AI 的東西要用自己的話重寫才能進主庫）。

這一包走的是同一條路，差別在落地方式——完整對照表與我們為什麼這樣選，寫在 `架構導覽.md` 第三節。一句話版：那邊是人先寫、AI 後編譯，庫的乾淨程度優先；這邊是 AI 先存、人後裁決，吞吐量優先，代價用制度補（禁寫區、判斷欄、隊列、每週三個數字）。

門檻降低的代價要先講清楚：三行判斷比重寫全文輕鬆，所以你很容易隨手亂填。填了跟想過了是兩回事，健康檢查裡的「未認證」數字就是用來抓這個的。

如果你是純個人思考型的使用者，不做內容也不接案，那篇文章的分離式做法對你更合適。
